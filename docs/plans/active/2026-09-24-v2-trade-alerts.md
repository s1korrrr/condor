# V2 confirmed-fill Telegram notifications

Objective: add readable V2 buy/sell notifications to the existing Condor worker and investigate the supplied execution logs. Completion: durable notification state, owner/recipient checks, partial-fill grouping, restart/retry tests, a scoped worker deployment and Telegram delivery evidence. Authority: live-adjacent notification service only; GET-only native reads, no orders, wallet changes, execution restart or funding-guard bypass. Root and native shared checkout dirt is preserved. Owning repo: Condor, branch feat/andrzej_telegram_trade_alerts, based on the deployed readable worker.

Design: optional `trade_alerts` boolean (default false), same Telegram poller/token, separate asynchronous five-second fill read loop. Existing allowlisted private users are recipients. SQL outbox records fills and notifications atomically, groups newly seen fills by native order, marks sent only after Telegram confirmation and persists across restarts. The initial activation timestamp suppresses historical replay; shutdown cancels the notification task before closing SQLite. No created/canceled event is labeled as an executed trade. A buy/sell notification is a fill update, not a claim of entire-order completion. Fees use native quote receipts; sell realized PnL stays unavailable when the feed has no cost basis. No maker/taker role is inferred from order type.

Delivery limits: Telegram offers no idempotent send key. A crash/timeout after remote acceptance but before local acknowledgment can repeat an alert; ordinary polls/restarts deduplicate by native fill identity. Native reads are bounded to 1000 newest fills and require overlap or activation-boundary coverage when full; a coverage gap holds reads and marks notifications delayed rather than silently skipping. /status exposes notification source delay. This is not exchange/event-stream exactly-once delivery. Raw receipt data stays in the existing private state directory.

Validation: tests/test_fleet_trade_alerts.py plus existing worker/view suites. Initial test failed because new module was absent; implementation then passed 38 tests. Cases cover initial-history suppression, partial fills grouped, restart persistence, failed-send retry, ordinary deduplication, malformed rows/fees, HTML escaping, absent sell basis, source identity rejection, recipient revocation and saturated-tail overlap. Existing command/navigation tests remain included. Production-image import and execution smoke required before update.

Rollback: use the preceding compose definition and scoped `up -d --no-deps --pull never condor-telegram`; restore private config backup if disabling alerts. Keep notification database and offsets intact. Native owners are not part of this release.
